If you're still running `kubectl apply -f` directly to production, this post is for you.

GitOps isn't just a buzzword—it's how modern teams deploy to Kubernetes without losing sleep. Here's how we set up FluxCD + Kustomize for our [Founding Pilot clients](/founding-pilot) to get auditable, automated, and safe deployments in production.

## Why GitOps? Why FluxCD?

**The Problem:**
- Manual kubectl commands have no audit trail
- "Works on my machine" syndrome across environments
- No easy rollback mechanism
- Configuration drift between clusters

**The Solution:**
Git as the single source of truth for your cluster state. Tools like FluxCD watch your Git repository and automatically sync changes to Kubernetes.

### FluxCD vs. ArgoCD vs. Jenkins X

We choose **FluxCD** for most startups because:

✅ Lightweight (runs in-cluster, no extra UI to maintain)
✅ Pull-based (more secure than push-based CI/CD)
✅ Native Helm + Kustomize support
✅ Multi-tenancy ready
✅ Strong RBAC and security posture

**When to use ArgoCD:** If you need a UI for non-technical stakeholders
**When to use Jenkins X:** If you're deep in the Jenkins ecosystem

## Architecture Overview

Here's the setup we implement:

```
┌─────────────────┐
│   GitHub Repo   │  ← Developers push here
│  (manifests/)   │
└────────┬────────┘
         │
         ↓ (Flux watches)
┌─────────────────┐
│  FluxCD Pods    │  ← Runs in Kubernetes
│  (flux-system)  │
└────────┬────────┘
         │
         ↓ (applies)
┌─────────────────┐
│   Kubernetes    │  ← Your apps run here
│   Workloads     │
└─────────────────┘
```

## Step-by-Step Implementation

### 1. Install FluxCD CLI

```bash
# macOS
brew install fluxcd/tap/flux

# Linux
curl -s https://fluxcd.io/install.sh | sudo bash

# Verify
flux --version
```

### 2. Bootstrap Flux in Your Cluster

```bash
export GITHUB_TOKEN=<your-github-pat>
export GITHUB_USER=<your-github-username>
export GITHUB_REPO=<your-gitops-repo>

# Bootstrap Flux
flux bootstrap github \
  --owner=$GITHUB_USER \
  --repository=$GITHUB_REPO \
  --branch=main \
  --path=clusters/production \
  --personal
```

This creates:
- `flux-system` namespace
- Flux controllers (source-controller, kustomize-controller, helm-controller, notification-controller)
- GitHub deploy key (read-only access to your repo)
- Initial commit with Flux manifests

### 4. Create Base Manifests

**`apps/base/api/deployment.yaml`:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
  namespace: default
spec:
  replicas: 2  # Overridden per environment
  selector:
    matchLabels:
      app: api
  template:
    metadata:
      labels:
        app: api
    spec:
      containers:
      - name: api
        image: myregistry.io/api:latest  # Overridden by CI
        ports:
        - containerPort: 8080
        env:
        - name: ENV
          value: "production"  # Overridden per environment
        resources:
          requests:
            memory: "256Mi"
            cpu: "250m"
          limits:
            memory: "512Mi"
            cpu: "500m"
```

**`apps/base/api/kustomization.yaml`:**
```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

resources:
  - deployment.yaml
  - service.yaml

commonLabels:
  app: api
  managed-by: kustomize
```

### 5. Create Environment Overlays

**`apps/overlays/production/api/kustomization.yaml`:**
```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

namespace: production

bases:
  - ../../../base/api

replicas:
  - name: api
    count: 5  # More replicas in prod

images:
  - name: myregistry.io/api
    newTag: v1.2.3  # Updated by CI

patches:
  - target:
      kind: Deployment
      name: api
    patch: |-
      - op: replace
        path: /spec/template/spec/containers/0/env/0/value
        value: "production"
      - op: add
        path: /spec/template/spec/containers/0/env/-
        value:
          name: DATABASE_URL
          valueFrom:
            secretKeyRef:
              name: api-secrets
              key: database-url
```

### 6. Create Flux Kustomization

**`clusters/production/api-kustomization.yaml`:**
```yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: api
  namespace: flux-system
spec:
  interval: 5m
  path: ./apps/overlays/production/api
  prune: true
  sourceRef:
    kind: GitRepository
    name: flux-system
  healthChecks:
    - apiVersion: apps/v1
      kind: Deployment
      name: api
      namespace: production
  timeout: 5m
```

Commit and push:
```bash
git add .
git commit -m "Add API deployment"
git push
```

Flux will automatically sync within 5 minutes (or force with `flux reconcile kustomization flux-system`).

### 7. Integrate with CI/CD

**GitHub Actions workflow to update image tags:**

```yaml
name: Deploy API

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Build and push Docker image
        run: |
          docker build -t myregistry.io/api:${{ github.sha }} .
          docker push myregistry.io/api:${{ github.sha }}

      - name: Update GitOps repo
        env:
          GITOPS_TOKEN: ${{ secrets.GITOPS_TOKEN }}
        run: |
          git clone https://$GITOPS_TOKEN@github.com/$GITHUB_USER/$GITHUB_REPO.git gitops
          cd gitops
          cd apps/overlays/production/api
          kustomize edit set image myregistry.io/api:${{ github.sha }}
          git config user.name "GitHub Actions"
          git config user.email "actions@github.com"
          git commit -am "Update API to ${{ github.sha }}"
          git push
```

## Advanced Features

### Image Update Automation

Let Flux automatically update images:

```yaml
apiVersion: image.toolkit.fluxcd.io/v1beta1
kind: ImageRepository
metadata:
  name: api
  namespace: flux-system
spec:
  image: myregistry.io/api
  interval: 1m

---
apiVersion: image.toolkit.fluxcd.io/v1beta1
kind: ImagePolicy
metadata:
  name: api
  namespace: flux-system
spec:
  imageRepositoryRef:
    name: api
  policy:
    semver:
      range: 1.x.x

---
apiVersion: image.toolkit.fluxcd.io/v1beta1
kind: ImageUpdateAutomation
metadata:
  name: api
  namespace: flux-system
spec:
  interval: 5m
  sourceRef:
    kind: GitRepository
    name: flux-system
  git:
    checkout:
      ref:
        branch: main
    commit:
      author:
        name: Flux
        email: flux@resiliotech.com
      messageTemplate: "Update {{range .Updated.Images}}{{println .}}{{end}}"
    push:
      branch: main
  update:
    path: ./apps/overlays/production
    strategy: Setters
```

## Best Practices

### 1. Use Separate Repos for App Code vs. GitOps Manifests
- App repo: Source code
- GitOps repo: Kubernetes manifests

**Why:** Different RBAC, different change frequency

### 2. Enable Drift Detection
Flux will alert if someone runs `kubectl apply` directly:

```yaml
spec:
  interval: 5m
  path: ./apps/overlays/production
  prune: true  # Delete resources removed from Git
  force: true  # Overwrite manual changes
```

### 3. Pin Flux Version
In production, pin the Flux version to avoid surprise upgrades:

```yaml
# clusters/production/flux-system/gotk-components.yaml
# Use specific version tag, not 'latest'
```

### 4. Secrets Management
**Never commit secrets to Git.** Use:
- **Sealed Secrets:** Encrypt secrets in Git
- **External Secrets Operator:** Pull from AWS Secrets Manager/Vault
- **SOPS:** Encrypted files with PGP/age keys

Example with External Secrets:
```yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: api-secrets
  namespace: production
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: aws-secrets-manager
    kind: SecretStore
  target:
    name: api-secrets
    creationPolicy: Owner
  data:
    - secretKey: database-url
      remoteRef:
        key: production/api/database-url
```

## Monitoring Flux

```bash
# Check Flux status
flux get all

# Check specific Kustomization
flux get kustomizations api

# Force reconciliation
flux reconcile kustomization api --with-source

# View logs
kubectl logs -n flux-system deploy/kustomize-controller -f
```

## When Things Go Wrong

### Rollback
Since everything is in Git:
```bash
git revert HEAD
git push
# Flux will automatically rollback
```

### Suspend Automated Updates
```bash
flux suspend kustomization api
# Make manual fixes
flux resume kustomization api
```

## What You Get

✅ **Audit trail:** Every change is a Git commit
✅ **Zero-touch deploys:** Push to Git → deployed in <5 min
✅ **Easy rollback:** `git revert` → automatic rollback
✅ **Drift prevention:** Manual changes get overwritten
✅ **Multi-environment parity:** Same manifests, different overlays
