# Serving Open-Source LLMs with vLLM on Kubernetes

Running an LLM in a notebook is easy. Running it in production with predictable latency, [sane GPU costs](/blog/ai-infrastructure-cost-optimization), and [safe deployments](/blog/model-canary-releases-shadow-traffic-guide) is where the real work starts.

For most teams serving open-source models, **vLLM + Kubernetes** is the gold standard. vLLM provides efficient inference through paged attention and [continuous batching](/blog/batching-strategies-llm-inference-throughput-vs-latency), while Kubernetes handles [multi-node inference](/blog/migrating-from-single-gpu-to-multi-node-inference-when-model-outgrows-one-machine), [GPU autoscaling](/blog/gpu-autoscaling-right-sizing-inference-clusters), and operational consistency.

## The Production vLLM Playbook

### 1. Accurate Capacity Planning
VRAM is your primary constraint. You must right-size your nodes based on [model weights and KV cache requirements](/blog/capacity-planning-llm-inference-gpu-memory-throughput-slas) to avoid OOMs and [high latency](/blog/why-your-llm-responses-are-slow-diagnosing-inference-latency-production). This is especially true for [Mixture-of-Experts (MoE) models](/blog/mixture-of-experts-moe-models-production-infrastructure-challenges-solutions), which have unique memory and serving requirements.

### 2. Intelligent Routing and Gateways
Don't expose your model servers directly. Use an [LLM Gateway](/blog/llm-gateway-architecture-routing-rate-limits-cost-controls) to manage rate limits, [token economics](/blog/llm-token-economics-tracking-controlling-inference-spend), and [PII filtering](/blog/data-privacy-rag-systems-pii-filtering-before-model).

### 3. Integrated Observability
A production vLLM deployment is incomplete without [deep observability](/blog/ai-observability-metrics-dashboards-that-matter). Track TTFT, tokens per second, and GPU duty cycle using [Prometheus and Grafana](/blog/setting-up-ml-model-monitoring-prometheus-grafana-complete-guide).

### 4. Zero-Downtime Updates
Ensure that model updates don't interrupt service by using [blue-green or rolling deployments](/blog/zero-downtime-model-updates-blue-green-rolling-deployments-ml-systems).

## Final Takeaway

vLLM on Kubernetes is the most powerful combination for serving open-source LLMs today. By focusing on VRAM right-sizing, gateway-level controls, and deep observability, you can build a serving stack that is both high-performing and operationally stable.
